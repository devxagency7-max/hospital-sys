# اتفاقيات الواجهة — مرجع التسليم

هذا الملف يُجيب عن بنود `10-PRE-CODING-CHECKLIST.md` التي كانت مفتوحة، ويُثبّت
القرارات التي بُنيت عليها الواجهة فعلًا. **هو المدخل الصحيح لمطور الباك-إند.**

---

## 1. القرارات المعمارية

| البند | القرار | لماذا |
|---|---|---|
| الراوتنج | SPA براوتر hash (`#/patients/1001`) | لا يحتاج إعداد خادم (rewrite rules)، فيعمل من أي مسار فرعي داخل شبكة المستشفى |
| الأنماط | Tailwind v4 عبر npm build | الـ tokens في `@theme` داخل `css/tailwind.src.css` — نقطة واحدة لتغيير الهوية |
| الوحدات | ES Modules أصلية، بدون حزم (bundler) | صفر خطوات بناء للـ JS؛ المتصفح يُحمّل الشاشة عند طلبها |
| الحالة | متدرّجة: متغير محلي ← `createStore` ← `appState` | لا مبرر لمكتبة حالة كاملة في شاشات CRUD |
| بناء الـ DOM | دالة `el()` لا `innerHTML` | بيانات المرضى والفواتير تُمرَّر كـ textNode، فالحقن (XSS) مستحيل بنيويًا |
| الاعتماديات | Tailwind فقط (أداة بناء) | صفر مكتبات في المتصفح — لا jQuery ولا أيقونات خارجية ولا مكتبة تواريخ |

### الخط واللغة

- الخط: **IBM Plex Sans Arabic** (مصمَّم للواجهات، أرقامه بعرض ثابت).
- النص عربي، **والأرقام لاتينية** (`ar-EG-u-nu-latn`): الأرقام الهندية (٠١٢)
  تكسر محاذاة الأعمدة المالية وتُربك النسخ إلى Excel.
- كل رقم وتاريخ يمر من `js/core/format.js`. لا تنسّق رقمًا داخل شاشة.

## 2. عقد الـ API

### 2.1 نقطة التبديل

كل طلب يمر من [`frontend/js/api/http.js`](../frontend/js/api/http.js).
للتحويل إلى باك-إند حقيقي، عدّل [`frontend/js/core/config.js`](../frontend/js/core/config.js):

```js
export const API = {
  mode: "live",        // كان "mock"
  baseUrl: "/api/v1",
  timeoutMs: 20000,
};
```

لا تعديل في أي شاشة أو مكوّن.

### 2.2 قائمة الـ endpoints المتوقَّعة

المصدر الحيّ هو جدول `ROUTES` في
[`frontend/js/api/mock-adapter.js`](../frontend/js/api/mock-adapter.js)،
وتُعرض أيضًا داخل التطبيق على `#/design-system?tab=data`.

### 2.3 شكل الاستجابة

**سجل واحد**

```json
{ "data": { "id": 1001, "name": "…" } }
```

**قائمة مُرقَّمة**

```json
{
  "data": [ … ],
  "meta": { "page": 1, "perPage": 25, "total": 148, "totalPages": 6 }
}
```

**خطأ** — أي حالة HTTP ≥ 400

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "راجع الحقول المظلَّلة.",
    "fields": { "phone": "رقم موبايل مصري غير صحيح." }
  }
}
```

`message` يُعرض للمستخدم مباشرة، فليكن **بالعربية وصالحًا للقراءة**.
`fields` اختياري ويُستخدم مع `VALIDATION_ERROR` فقط؛ الواجهة تعرضه تحت الحقول.

رموز `code` المعروفة في [`js/core/errors.js`](../frontend/js/core/errors.js):
`VALIDATION_ERROR` · `NOT_FOUND` · `CONFLICT` · `FORBIDDEN` · `UNAUTHENTICATED` ·
`SERVER_ERROR` · `NOT_IMPLEMENTED` · `NETWORK_ERROR` · `TIMEOUT`.

### 2.4 معاملات الاستعلام للقوائم

كل جدول يرسل هذه المعاملات، ويتوقع **التنفيذ على الخادم**:

| المعامل | المثال | الملاحظة |
|---|---|---|
| `page` | `2` | يبدأ من 1 |
| `perPage` | `25` | الافتراضي 25 |
| `search` | `احمد` | بحث حر على حقول المجموعة |
| `sort` | `total` | اسم الحقل |
| `order` | `asc` \| `desc` | |
| `dateFrom` / `dateTo` | `2026-09-01` | على حقل التاريخ الأساسي للمجموعة |
| أي حقل آخر | `status=unpaid,partially_paid` | الفاصلة = «أو» |

> **مهم:** الفلترة والترتيب والترقيم **ليست** محلية في المتصفح. الجدول يطلب
> صفحة ويعرضها فقط. الفلترة المحلية تبدو سليمة على 148 صفًا تجريبيًا ثم تنهار
> على 80 ألف فاتورة حقيقية.

### 2.5 صيغ التبادل

- التواريخ: `YYYY-MM-DD`. التاريخ والوقت: ISO 8601 بمنطقة زمنية.
- المبالغ: أرقام عشرية بمنزلتين (لا نصوص).
- المعرّفات: أعداد صحيحة.

### 2.6 البحث العربي

الواجهة تُطبّع نص البحث قبل إرساله ([`js/core/text.js`](../frontend/js/core/text.js)):
`أ إ آ ← ا` · `ى ← ي` · `ة ← ه` · إزالة التشكيل · الأرقام الهندية ← لاتينية.

**على الباك-إند تطبيق تطبيع مكافئ** (مثلاً `utf8mb4_unicode_ci` + دالة تطبيع)،
وإلا لن يجد من يكتب «احمد» المريض «أحمد» — وهي أكثر شكوى متكررة في الأنظمة العربية.

## 3. نموذج الصلاحيات

### 3.1 القاعدة

**ممنوع كتابة الصلاحيات داخل الصفحات.** لا تكتب `if (user.role === 'admin')` أبدًا.
المفاتيح كلها في [`js/core/permissions.js`](../frontend/js/core/permissions.js)،
والشاشة تسأل `can('patients.create')`.

### 3.2 الصيغة

`<module>.<action>` — مثل `billing.invoice.create`.
تُدعم البادئة: `patients.*` تمنح كل صلاحيات موديول المرضى، و `*` تمنح كل شيء.

### 3.3 نقاط التطبيق

| المكان | السلوك |
|---|---|
| الشريط الجانبي | المجموعة التي لا يملك المستخدم أي عنصر فيها لا تظهر |
| الراوتر | `route.permission` يُفحص قبل تحميل الشاشة → شاشة «لا تملك صلاحية» |
| الأزرار | `button({ permission })` يُعيد `null` — الزر الممنوع لا يُعرض معطّلاً |
| التبويبات | التبويب الممنوع يُحذف من الشريط |

### 3.4 تحذير أمني

هذه **طبقة تجربة مستخدم فقط**. إخفاء زر ليس أمانًا.
التحقق الملزِم من كل صلاحية مسؤولية الباك-إند على كل endpoint.

### 3.5 الأدوار الابتدائية

`admin` · `manager` · `accountant` · `receptionist` · `doctor` · `pharmacist` ·
`lab_technician` · `storekeeper` — نقطة بداية واقعية يحددها العميل نهائيًا.

### 3.6 المصادقة

غير منفَّذة (Phase 7). النائب الحالي هو `session` في `permissions.js`.
عند التنفيذ: املأ الجلسة من التوكن عبر `setSession()` — ولا يتغير شيء آخر.
مبدّل الأدوار في الهيدر **أداة تطوير** تُزال عند ربط المصادقة.

## 4. تغطية الشاشات

`04-MODULES-AND-SCREENS.md` يذكر **105 شاشة**. خريطة التنقل تسجّل منها
**81 مدخلاً**. الفرق ليس نقصًا — هو تصنيف:

| النوع | العدد | أين تعيش |
|---|---|---|
| مداخل في الشريط الجانبي | 81 | `js/config/navigation.js` |
| شاشات تفاصيل (مسار ديناميكي) | ~12 | `/patients/:id` — تُسجَّل في `DYNAMIC` داخل `routes.js`، ولا تظهر في الشريط لأنها لا تُفتح إلا من سجل |
| أقسام داخل شاشة (تبويبات) | ~8 | «خدمات المريض» و«مدفوعاته» و«سجله» تبويبات في ملف المريض لا شاشات مستقلة |
| لوحات داخل لوحة التحكم | ~6 | «نظرة الإيرادات» و«تنبيهات المخزون» بطاقات في لوحة واحدة |

**أمثلة على التصنيف:**

- `Patient profile` / `Edit patient` → `/patients/:id` (ديناميكي)
- `Patient services` / `Patient payments` / `Patient history` → تبويبات داخل الملف
- `Invoice details` → `/billing/invoices/:id`
- `Revenue overview` / `Inventory alerts` / `Pending approvals` → بطاقات في `/`

كل مدخل في الشريط يحمل وسم مرحلته (`P1`…`P6`)، والشاشة غير المنفَّذة بعد تعرض
صفحة **«مخطَّطة في المرحلة كذا»** صريحة — لا رابط مكسور ولا صفحة فارغة تبدو معطّلة.

## 4أ. الحساب المالي

### القاعدة

**ممنوع حساب أي مبلغ في شاشة أو مكوّن.** كل رياضيات المال في وحدتين خالصتين:

| الوحدة | المسؤولية |
|---|---|
| [`js/core/money.js`](../frontend/js/core/money.js) | الحساب بالقروش كأعداد صحيحة — جمع، طرح، ضرب، توزيع بلا ضياع قرش |
| [`js/domain/billing.js`](../frontend/js/domain/billing.js) | قواعد العمل — دورة حياة الفاتورة، المرتجع، إشعار الدائن، التسوية، كشف الحساب |

كلاهما خالٍ من DOM ويعمل في Node، ومُغطّى بـ 175 اختبارًا في
[`tests/billing.test.mjs`](../frontend/tests/billing.test.mjs). اختبار معماري في
[`tests/architecture.test.mjs`](../frontend/tests/architecture.test.mjs) يمنع عودة
الحساب إلى طبقة العرض، ويحرس بالاسم فصل المرتجع عن إشعار الدائن تحديدًا.

### لماذا القروش لا الجنيهات

`0.1 + 0.2 !== 0.3`. قياس فعلي على البيانات الحالية أعطى انحرافًا قدره
`9.31e-10` في جمع 225 فاتورة؛ ومع نمو البيانات يصل إلى قرش كامل فيظهر ميزان
لا يتوازن ولا يُعرف سببه. الحساب الداخلي كله بالقروش، والتحويل عند العرض فقط.

### نموذج الفوترة — مرجع كامل منفصل

**الشرح الكامل والعلاقات والأمثلة الرقمية في
[`12-BILLING-DOMAIN-MODEL.md`](12-BILLING-DOMAIN-MODEL.md) — اقرأه قبل أي شاشة
فوترة.** هنا الخلاصة الدنيا فقط:

- **Invoice** دورة حياة لا رجوع فيها: `draft → issued → cancelled`. بعد
  `issued` تتجمَّد `total`/`discount`/`tax` إلى الأبد — `assertMutable()` تمنع
  أي تعديل صامت.
- **Refund** (مرتجع) و **Credit Note** (إشعار دائن) **كيانان منفصلان تمامًا،
  لا نسخة من بعضهما:**

  ```text
  effectiveTotal = total − Σ(إشعارات دائن معتمدة)     ← جانب الفاتورة
  netPaid        = Σ(دفعات) − Σ(مرتجعات معتمدة)        ← جانب التحصيل
  remaining      = effectiveTotal − netPaid
  ```

  مرتجع يُخفّض ما حُصِّل؛ إشعار دائن يُخفّض ما يُستحق. فاتورة مُسدَّدة بالكامل
  اعتُمد عليها إشعار دائن تصبح **`overpaid`** لا `paid` — رصيد دائن للمريض،
  لا مديونية عليه.
- **الفاتورة الملغاة**: كل حقل مالي فيها صفر، `total` فقط يبقى للتدقيق.
  استخدم `isFinalized()` / `totalOutstanding()` / `summarizePatientAccount()` —
  لا تكرار شرط `status !== "cancelled"` يدويًا، فهو بالضبط ما انحرف سابقًا.

### الضمانة التي يجب أن يحفظها الباك-إند

```text
رصيد المريض  ===  مجموع `remaining` لفواتيره الصادرة (غير المسودة وغير الملغاة)
```

رقم كشف الحساب ورقم جدول الفواتير يجب أن يخرجا من نفس الحساب دائمًا.

## 4ب. اتجاه النص والأرقام (RTL)

فحص فعلي في المتصفح أعطى ثلاث فئات — والقاعدة مختلفة لكل منها:

| الفئة | مثال | السلوك | المطلوب |
|---|---|---|---|
| عدة مقاطع لاتينية/رقمية | `0101 234 5678` | **يُعاد ترتيبها** → `5678 234 0101` | عزل إلزامي |
| رقم + كلمة عربية | `1,200.50 ج.م` · `120 علبة` | تنقلب — **وهذا صحيح** | **لا تعزلها** |
| مقطع واحد | `P-1001` · `12.5%` · `INV-2026-0001` | آمن منفردًا، هشّ بجوار نص عربي | عزل احتياطي |

### الأدوات

CSS — [`css/tailwind.src.css`](../frontend/css/tailwind.src.css):
`ltr-isolate` · `ltr-start` · `num`

مكوّنات — [`components/common/value.js`](../frontend/components/common/value.js):

| الدالة | الاستخدام |
|---|---|
| `ref(value)` | مرجع تجاري: كود مريض، رقم فاتورة، كود صنف، رقم تشغيلة |
| `code(value)` | قيمة تقنية: رمز خطأ، مفتاح صلاحية، مسار endpoint |
| `phoneValue(value)` | هاتف — معزول وبلا التفاف |
| `range(from, to)` | نطاق رقمي بين قيمتين |
| `codeBlock(text)` | كتلة JSON أو كود متعددة الأسطر |
| `ltr(value)` | أي نص لاتيني حر |

**ممنوع** `[direction:ltr]` أو `style="direction:..."` مباشرة — اختبار معماري يرفضها.

### ملاحظتان

- `format.phone()` تفصل المجموعات بمسافة غير فاصلة (U+00A0): تمنع الالتفاف
  وتُبقي الرقم مقطعًا واحدًا. لا حروف عزل غير مرئية في النص نفسه، فيبقى نظيفًا
  عند النسخ والتصدير.
- التواريخ من `Intl` محمية أصلًا بعلامات اتجاه مدمجة — لا تعزلها يدويًا.
- طبقة التصدير (CSV/Excel) تستدعي `format.stripBidi()` لتنظيف أي حرف تحكّم.

## 4ج. دورة حياة الشاشة

المكوّنات التي تُنشئ مستمعات أو مؤقتات تُسجّل تنظيفها بنفسها عبر
[`js/core/lifecycle.js`](../frontend/js/core/lifecycle.js):

```js
registerCleanup(() => clearInterval(timer));
```

الراوتر يُشغّل كل الدوال المسجَّلة قبل رسم الشاشة التالية.

الصفحة لا تحتاج أن تعرف بوجود المكوّن — وهذا مقصود: المكوّن قد يُنشأ داخل
تبويب كسول لا تملك الصفحة مرجعًا له. الاعتماد على أن تُعيد كل صفحة
`{ element, destroy }` يدويًا لم يكن يعمل عمليًا، وكانت نتيجته بحثًا مؤجَّلًا
يُنفَّذ بعد مغادرة الشاشة فيكتب فلاتره في رابط الصفحة التالية.

## 6. التسمية ومواضع الملفات

```text
frontend/
├── js/core/      أساسيات لا تعرف شيئًا عن الشاشات (dom, router, format, …)
├── js/api/       طبقة البيانات — الشاشات تستدعيها ولا تعرف أي URL
├── js/mock/      بيانات تجريبية معزولة تمامًا عن الواجهة
├── js/config/    خريطة التنقل وجدول المسارات
├── components/   مكوّنات قابلة لإعادة الاستخدام
└── pages/        شاشة واحدة لكل ملف: <اسم>.page.js
```

- الملفات: `kebab-case` — `patient-list.js` لا `PatientList.js`.
- شاشة = `pages/<module>/<screen>.page.js` تُصدِّر دالة افتراضية تُعيد عنصر DOM.
- الشاشة التي تحتاج تنظيفًا تُعيد `{ element, destroy }` والراوتر يستدعي `destroy`.
- ممنوع `onclick="..."` في HTML — المعالجات في JS دائمًا.

### إضافة شاشة جديدة

1. أضف المدخل في `js/config/navigation.js` (المسار، الصلاحية، المرحلة).
2. أنشئ `pages/<module>/<screen>.page.js`.
3. سجّلها في `IMPLEMENTED` داخل `js/config/routes.js` — تختفي صفحة «مخطَّطة» تلقائيًا.

### إضافة حالة جديدة

سجّلها في `js/core/statuses.js` أولاً. `statusBadge` تُحذّر في الـ console على
أي حالة غير مسجَّلة بدل أن تخترع لونًا.

## 7. ما لم يُنفَّذ بعد (بصراحة)

- **الخط من Google Fonts**: يُستضاف محليًا في `assets/fonts/` قبل التسليم —
  شبكة المستشفى قد تكون مغلقة على الإنترنت الخارجي.
- **الوضع الداكن**: الـ tokens مهيّأة كمتغيرات CSS لكن لا توجد لوحة داكنة.
- **الترجمة الإنجليزية**: البنية تسمح بها (الخصائص المنطقية مستخدمة في كل مكان،
  والدرج يتعامل مع الاتجاهين)، لكن النصوص مكتوبة مباشرة ولم تُستخرج إلى قاموس.
- **التصدير الفعلي** (PDF/Excel/CSV): المنطق الذي يمنع التصدير الناقص جاهز،
  أما توليد الملفات فهو عمل المرحلة 5.
- **ثغرة `braces`** في `npm audit`: داخل `@parcel/watcher` التابع لـ
  `@tailwindcss/cli`. أداة بناء فقط (مراقبة الملفات)، لا تصل إلى المتصفح ولا
  إلى الإنتاج. لا يمكن ترقيعها دون انتظار تحديث Tailwind.
